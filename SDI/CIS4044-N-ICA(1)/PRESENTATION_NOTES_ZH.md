# ICA 讲解提纲

## 1. 项目目标

这个项目处理 Open-Meteo 历史天气数据，分成三个阶段：

- Phase 1：从 SQLite 数据库查询国家、城市、温度和降雨统计。
- Phase 2：用 Matplotlib 把数据库查询结果变成图表。
- Phase 3：用 `requests` 调用 Open-Meteo API，把新的天气数据写回 SQLite。

## 2. 代码结构

- `ICA/common.py` 放公共逻辑，例如数据库连接、日期校验、城市经纬度读取。
- `ICA/phase_1.py` 负责 SQL 查询，并且所有浮点数输出保留 2 位小数。
- `ICA/phase_2.py` 负责生成图表，输出到 `charts/` 文件夹。
- `ICA/phase_3.py` 负责 API 请求、JSON 解析、数据库更新。
- `ICA/main.py` 是统一入口，可以运行 demo、菜单、生成图表或更新天气数据。

## 3. 可以重点展示的功能

1. 运行 `python3 -m ICA.main demo`，展示 Phase 1 查询和自动生成图表。
2. 打开 `charts/` 下的 6 张图，说明每张图对应的天气分析。
3. 展示 `tests/test_weather_app.py`，说明不是只靠手动试，而是保留了测试用例。
4. 说明 Phase 3 没有直接复制 Open-Meteo 示例，而是自己构建请求参数并处理异常。

## 4. 风险与安全点

- SQL 查询使用参数占位符，减少 SQL 注入风险。
- 日期和年份会先校验，格式不对会抛出错误。
- API 可能超时或返回结构变化，所以代码会捕获请求异常并检查 JSON 字段。
- 更新数据库时先删除同一城市同一天的旧数据，再插入新数据，避免重复记录。

## 5. 测试说明

测试命令：

```bash
python3 -m unittest discover -s tests -v
```

测试覆盖：

- 国家和城市查询数量。
- 年平均温度和 7 天降雨统计。
- 错误日期校验。
- 图表文件是否成功生成。
- Open-Meteo JSON 是否能解析。
- 数据库更新是否会替换重复日期。
- 网络超时是否被正确处理。

## 6. 总结话术

这个实现满足 ICA 的三阶段要求，并且额外加入了统一入口、菜单、图表证据、异常处理和自动化测试。整体设计把公共逻辑抽到 `common.py`，每个阶段职责清楚，方便运行、讲解和后续扩展。
