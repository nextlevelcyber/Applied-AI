# SDI ICA 演示讲稿（约5分钟）

适用范围：CIS4044-N（Software for Digital Innovation）ICA 演示/讲述稿。
项目：`CIS4044-N-ICA(1)/` — Historical Weather Data（Open-Meteo 数据集）。

***

## 1. 开场（约20秒）

大家好，我今天演示的是 SDI 模块的 ICA 项目，题目是 Historical Weather Data，基于 Open-Meteo 这个开放气象数据源，用 Python 和 SQLite3 搭建了一套天气数据的查询、可视化和实时抓取系统，分三个阶段实现，我按顺序依次介绍。

## 2. 占分结构（约20秒）

Phase 1 是 SQL 查询，占15%；Phase 2 是用 Matplotlib 画图表，占15%；Phase 3 权重最高占30%，要求实时抓取 Open-Meteo 的历史数据，而且直接用官方示例代码的话成绩会封顶在及格线，所以我自己用 requests 重写了这部分逻辑，才能拿到更高等级。

【此时可以切到文件管理器或 VS Code，展示 ICA/ 目录结构】

## 3. 代码架构（约40秒）

代码在 `ICA/` 目录下五个文件：`common.py` 是公共逻辑，比如数据库连接和日期校验；`phase_1.py` 是所有 SQL 查询，包括按城市统计年均气温、七天平均降水量，还有用窗口函数 RANK 做的"每年最湿城市"加分查询；`phase_2.py` 用 Matplotlib 生成六张图表；`phase_3.py` 负责调用 API、解析数据再写入数据库，我做了删除后重新插入的去重处理；`main.py` 是命令行入口，提供 demo、menu、charts、update-weather 四个子命令。

## 4. 数据库设计（约20秒）

数据库是 SQLite，三张表：`countries`、`cities`、和天气记录表 `daily_weather_entries`，通过外键关联，目前覆盖两个国家、四个城市，2020到2024年共七千三百多条记录，所有查询都是参数化 SQL，避免注入风险。

## 5. 现场演示（约90秒）

接下来实际运行一下。

【切换到终端，运行 `python main.py demo`，展示 Phase 1 查询结果打印在终端】

这是 demo 模式，跑一遍 Phase 1 的核心查询，可以看到每个城市每年的平均气温和降水量。

【运行 `python main.py charts`，打开 `charts/` 文件夹展示生成的 PNG 图表】

这一步调用 Phase 2 的绘图函数，生成六张图表，包括降水趋势图和气温散点图，都是基于数据库里的真实数据。

【运行 `python main.py update-weather`，展示实时抓取 Open-Meteo 数据并写入数据库】

这是 Phase 3，真实请求 Open-Meteo 归档接口，解析返回的每日天气 JSON 数据后写回数据库，如果记录已存在会先删除旧的再插入新的，保证不重复。

## 6. 测试（约30秒）

测试上写了15个单元测试，覆盖三个阶段的查询、绘图和 API 调用，API 部分用 mock 模拟网络请求，全部通过；报告里另外整理了13个黑盒测试用例，覆盖正常、边界和异常输入，也都是通过状态。

## 7. 设计取舍与现状（约30秒）

两个值得一提的设计决定：Phase 3 坚持自己写 requests 逻辑而不用官方示例，为了拿到更高等级；去重用的是删除后插入，而不是数据库唯一约束，这是还能优化的地方。可选加分项只做了命令行这一项。整体上三个阶段功能都已实现并通过测试，报告字数比要求略少，会再补充。

## 8. 结束语（约10秒）
